# Task 11: Authentication Integration - Add AuthenticationStateProvider to Blazor components

## Description

Integrate ASP.NET Core Identity authentication state into Blazor Server components by adding AuthenticationStateProvider configuration and updating existing pages with authorization components. This task establishes the foundation for user-aware UI components throughout the application.

## Acceptance Criteria

- [ ] CascadingAuthenticationState is added to App.razor
- [ ] AuthorizeView components are integrated into existing pages
- [ ] Program.cs is configured with proper Blazor authorization services
- [ ] Authentication state is accessible in all Blazor components
- [ ] Unauthorized users see appropriate fallback content
- [ ] Pages requiring authentication redirect properly
- [ ] No compilation errors after integration

## Technical Details

### App.razor Updates
```razor
<CascadingAuthenticationState>
    <Router AppAssembly="@typeof(App).Assembly">
        <!-- existing router configuration -->
    </Router>
</CascadingAuthenticationState>
```

### AuthorizeView Integration
- Update main pages (Index, PromptsList, etc.) with AuthorizeView wrappers
- Add NotAuthorized content for unauthorized users
- Implement role-based views where applicable

### Program.cs Configuration
```csharp
builder.Services.AddAuthentication()
    .AddIdentityCookies();

builder.Services.AddAuthorizationBuilder();

// Configure Blazor authorization
builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents()
    .AddAuthenticationStateSerialization();
```

### Component Updates
- Wrap sensitive UI sections with `<AuthorizeView>`
- Add authentication state parameter to components needing user context
- Update navigation components to show/hide based on auth state

## Dependencies

- **Task 10**: ASP.NET Core Identity Setup must be completed
- Identity tables and configuration must be in place
- Authentication middleware must be configured
